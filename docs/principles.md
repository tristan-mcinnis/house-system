# Principles

Each principle states what it means, why it exists, and where it is enforced. A
principle without an enforcement point is an intention; this list keeps the two
apart.

## 1. One visual rule

Every House app draws its colour, type, spacing, radius, shadow and control
height from one generated set of tokens, and composes one registered set of
shared components. An app never retypes a value and never invents a component.

*Why:* the family feels like one product line, and a change lands everywhere at
once. *Enforced by:* `design-system` tokens and the generated file an app
commits; the design lint; the design drift flag in the atlas. *See:*
[architecture](architecture.md).

## 2. One code rule

One Swift rule covers actors, `Sendable`, structured concurrency, the test
framework and platform floors. Each repository states its own floor and links to
the rule; it never copies the rule into itself.

*Why:* copied rules drift, and a floor stated twice is a floor that will
disagree with itself. *Enforced by:* `design-system/SWIFT.md`, each repository's
own contract file, and review.

## 3. Local first, private by default

Inference, capture and synthesis run on the machine. A hosted service is a named
exception with a stated reason. No app quietly uploads content.

*Why:* the tools hold a person's screen, voice and meetings. *Enforced by:*
`local-models` as the serving layer, per-app privacy notes, and the catalog's
`connectors` records, which name every outbound lane.

## 4. One fact, one owning record

Every fact has one owner. Derived views are regenerated, never hand-edited. A
session cache, a generated map, a screenshot or a subagent report is evidence,
not truth.

*Why:* two records of one fact inevitably disagree, and the reader cannot tell
which is stale. *Enforced by:* the sources table in the catalog, the validator's
single-authority check, and the repository contracts.

## 5. Each product owns its repository

Every House product is an independent repository. The group directory holds no
Git repository and no build. A shared capability graduates into its own organ
with a named owner; it does not become a folder in a shell.

*Why:* independent history, independent release, independent failure. A monorepo
would couple the release of a dictation tool to the release of a launcher.
*Enforced by:* the group contract and the atlas.

## 6. Maturity is stated, not implied

A component is `current`, `experimental` or `aspirational`, and the catalog says
which. `current` means relied on. A built thing that is not relied on is
`experimental`. A design is `aspirational` until code exists.

*Why:* overstating maturity is how a system loses track of what is real.
*Enforced by:* the validator's status enum, and review.

## 7. Generated views are disposable

A generated file carries a header that says it is generated and names its
generator. It is regenerated by a command and never edited by hand.

*Why:* hand edits to generated output are silent divergence. *Enforced by:*
`make map` and `make check`, which fails when the committed map is stale.

## 8. Maker then checker

Whoever builds a thing does not ship its verdict. Verification runs in a fresh
context, against the artifact, with the exact command recorded.

*Why:* the builder's assumptions are exactly what needs testing. *Enforced by:*
the subagent roster and the workflow rules; the plan that created this
repository ran separate review and verification passes.

## 9. Irreversible steps have a human gate

Publishing, spending, signing, making a repository public, deleting, and sending
communication all wait for an explicit human decision. Silence is not approval,
and a plan is not permission.

*Why:* these actions cannot be taken back, and their cost is not the agent's to
bear. *Enforced by:* the draft-only communication policy, the no-silent-publish
policy, and the human gates recorded in [distribution](distribution.md).

## 10. One verb per surface

Each app answers one question well. A second verb either belongs in an existing
surface or in a new app, not in a settings pane.

*Why:* scope creep is the usual way a small tool stops being a small tool.
*Enforced by:* the surfaces table and review.

## 11. Reference, do not duplicate

The catalog references `house/atlas.yaml`, `design-system` and each product's
own records. It does not copy their content. Project slugs are cross-checked
against the atlas during validation so the two cannot drift apart silently.

*Why:* a second registry is a second thing to keep true. *Enforced by:*
`tools/validate_catalog.py`.

## 12. State the boundary

When something is out of scope, say so in the artifact. The catalog says what it
does not own; this repository says it ships nothing; each app says what leaves
the machine.

*Why:* an unstated boundary is read as a promise. *Enforced by:* review, and the
scope statement at the top of the catalog.
